# Cutroom

Рабочее название. Персональная монтажная на своём сервере: канбан роликов, монтажный агент по вашей подписке (Claude Code или Codex CLI), версии и правки до принятия.

Версия 0.3 — проверка архитектуры. Монтаж: паузы, повторные дубли, звуки без слов, правки по времени, субтитры, моушен-графика на Remotion, материалы автора, музыка и звуковые эффекты из его библиотеки. Стиль задаёт пакет вкуса, раскладку вокруг лица и её проверку — ядро.

Cutroom — полный цикл: результат работы — готовый ролик. Проектов для монтажных программ (Final Cut, DaVinci Resolve, Premiere) он не выгружает, на выходе только финальный файл.

## Как это работает

```
Браузер ──► app (веб, API, SQLite, терминал)
                │  очередь в SQLite
                ▼
            worker ──► OpenRoughCut core: паузы, Whisper, дубли
                   ──► агент (claude -p / codex exec) с командой `cutroom`:
                         decisions.json, overrides.json → `cutroom cut` → склейка
                         graphics.json, custom/*.tsx → `cutroom gfx check`, `cutroom gfx still` → кадры
                   ──► FFmpeg: склейка; Remotion: графика, материалы и звук поверх склейки
                   ──► финал: полное разрешение или 1080p с графикой
```

- Один образ, два сервиса: `app` и `worker`. Caddy с HTTPS включается профилем `https` для сервера с доменом.
- Все данные лежат в томе `cutroom-data` (`/data`): ролики, база, профиль вкуса, модели Whisper. Там же `HOME` агента с его входом в подписку.
- Ядро OpenRoughCut (`packages/core`) копируется в образ при сборке из соседнего checkout.

## Ядро и пакеты вкуса

Ядро даёт механику, одинаковую для любого стиля:
- поиск лица в записи (OpenCV YuNet, один раз на исходник);
- безопасные зоны Shorts, Reels и TikTok;
- раскладку элементов выше или ниже лица и над субтитрами (`position: "auto"`);
- проверку `cutroom gfx review`: каждый элемент рендерится отдельно на прозрачном кадре и сравнивается с лицом, субтитрами и безопасной зоной;
- общие правила движения и встроенные элементы.

Пакет вкуса задаёт стиль: тему, шрифты, субтитры по умолчанию, свои компоненты, замены встроенных элементов и правила для агента. Встроенный пакет — `packs/base` («Базовый»). Другие устанавливаются архивом в «Настройки → Стиль монтажа». Каждая версия хранит копию своего пакета в `pack/`. Формат описан в [packs/README.md](packs/README.md).

Проверку раскладки запускают агент и сам worker. Если агент закрыл лицо или субтитры, он получает ошибки и второй заход. Итог проверки попадает в сообщение версии.

## Модели агентов

В «Настройки → Агент» выбираются модель и уровень рассуждений для Claude Code (`--model`, `--effort`) и Codex (`-m`, `model_reasoning_effort`). «По умолчанию» — модель, которую CLI выбирает для подписки. Фактическая модель версии пишется в `build.json` и видна в строке версии.

## Распознавание речи и словарь

В «Настройки → Распознавание речи» выбирается модель Whisper. По умолчанию — `small`: на русской речи она реже путает термины и окончания. Распознавание идёт по фразам, и запись в 99 секунд разбирается за 3 минуты (Docker на Mac, 10 ядер). `base` примерно в 4 раза быстрее, но пишет «не рассеть» вместо «нейросеть». `large-v3-turbo` без видеокарты в 4 раза медленнее самой записи. Каждая запись распознаётся один раз для каждой модели, результат кэшируется.

Словарь автора копится в базе и действует на все ролики:

- **Написание** («нейросеть», «Claude Code») уходит в Whisper подсказкой (`--prompt`) при распознавании новых записей. Подсказка помогает слабо, главную работу делают замены.
- **Замена** («не рассеть» → «нейросеть») исправляет расшифровку каждой новой версии. Время слов сохраняется, поэтому субтитры, `transcript.md` и единицы `u1…` у агента уже исправлены. Решения по дублям переносятся, так как id единиц не меняются. Сырая расшифровка остаётся в кэше анализа.
- Агент предлагает замены в `dictionary.json`. Если автор сам назвал написание в правке к этой версии, замена применяется сразу. Иначе она приходит в чат ролика карточкой «Да / Нет» и остаётся в списке предложений в настройках. Отклонённую замену агент больше не предложит.
- Замена действует на все ролики или только на один.
- Устойчивые предпочтения автора агент предлагает в `remember.json`. Они тоже приходят в чат карточкой «Да / Нет»; «да» дописывает строку в профиль вкуса в раздел «Запомнено из правок», «нет» запоминает отказ, и это предложение больше не появится. Предложения из старых версий, где агент писал их только в `reply.md` («Предлагаю запомнить»), Cutroom один раз собирает при запуске. Словарь версии замораживается в `context.json`, поэтому изменения словаря попадают только в следующую версию.

## Библиотека и материалы

- **Библиотека** («Настройки → Библиотека», `/data/library/music|sfx|other`) общая для всех роликов: треки, звуковые эффекты, логотипы и заставки. Cutroom не поставляет в неё свою музыку: треки загружает автор.
- **Встроенные эффекты** (`sounds/`, в образе): 195 коротких звуков Kenney (CC0), разложенных по ролям — щелчок, клавиша, переключатель, появление, открыть/закрыть, прокрутка, успех, уведомление, ошибка, сбой, рост, падение, бумага, удар, монеты, стекло. Агент видит их в `media.md` рядом с эффектами автора и ссылается как `sounds/click/click-1.ogg`; эффекты автора с подходящим смыслом у него в приоритете. Послушать — во вкладке «Звуковые эффекты» библиотеки. Источники и лицензия — `sounds/LICENSE.txt`. Если автор сам отметил трек музыкой по умолчанию, агент ставит его фоном в каждый ролик, пока автор не попросит иначе.
- **Материалы ролика** (при создании ролика или на его странице, `/data/videos/<id>/assets`): картинки, видеовставки и звук для одного ролика. Где их показать, автор пишет в брифе или правке.
- Агент видит список в `media.md` и ссылается на файлы в `graphics.json`: `library/sfx/Whoosh 1.mp3`, `assets/screen.png`. Картинки и видео ставятся элементами `image` и `video`, звук — массивом `audio` (`music` и `sfx`).
- Музыка идёт через склейки без перезапуска и приглушается под речью, в паузах длиннее 0,8 с поднимается. Эффект привязан к секунде исходника, как графика; эффект в вырезанном месте не звучит, `cutroom gfx check` предупредит.
- Версия хранит жёсткие ссылки на использованные файлы в `media/`, поэтому удаление файла из библиотеки не ломает её превью и финал.
- Звук и вставки сводит Remotion в превью и финал.

## Очередь и уведомления

- **Очередь монтажа** («Настройки → Очередь монтажа»): по очереди или одновременно, до 4 роликов. По умолчанию по очереди. Настройка действует без перезапуска; при уменьшении начатые задачи доходят до конца, новые ждут. Один ролик никогда не идёт в двух задачах сразу. Страница показывает ядра и память, доступные Docker, и предлагает предел: примерно 4 ядра и 4 ГБ на параллельный монтаж.
- **Telegram** («Настройки → Уведомления»): автор вставляет токен своего бота из @BotFather, открывает бота по одноразовой ссылке и нажимает «Start». Код в ссылке не даёт привязать чужой чат. Бот пишет, когда новая версия ждёт ревью, монтаж не удался или финальный файл готов; каждое событие отключается.
- В сообщении есть ссылка на ролик по адресу из настройки «Адрес Cutroom для ссылок» (по умолчанию `https://CUTROOM_DOMAIN` или адрес страницы при подключении). Если Telegram не принимает адрес в кнопке, например `localhost`, ссылка приходит текстом. С телефона откроется только адрес сервера.
- Токен хранится в SQLite на сервере и не возвращается в браузер. Бот с webhook не подходит: Cutroom читает `/start` через `getUpdates`. Ошибка отправки не ломает монтаж и видна в настройках.

## Громкость

«Настройки → Звук»: громкость голоса в готовом ролике (по умолчанию −14 LUFS, как выравнивают Reels, Shorts и TikTok), эффекты (−10 дБ от голоса), музыка под голосом (−20 дБ) и в паузах (−12 дБ).

- После склейки Cutroom измеряет голос (EBU R128, integrated LUFS), а каждый файл музыки и эффектов версии — один раз, результат в `sound.json` версии. Уровень трека считается от голоса, поэтому тихий щелчок и громкий стингер звучат одинаково относительно речи.
- `volume` в `graphics.json` — доля от уровня автора (≤ 1): агент может сделать звук тише, но не громче настроек.
- Последний шаг превью и финала — одно усиление всего микса до цели и лимитер на −1 дБ. Видео копируется, звук перекодируется.
- Настройки замораживаются в `context.json` версии: финал звучит как её превью. Версии, собранные до этого, сохраняют прежние линейные громкости и не выравниваются.

## Расходы агента

Каждый прогон агента, включая повторную попытку после проверки, записывается в базу (`agent_runs`): ролик, версия, агент, модель, токены (вход, запись и чтение кэша, выход, размышления) и стоимость. Видно в строке версии, на странице и карточке ролика и в «Настройки → Расходы» (итог, по роликам, моделям и месяцам).

- Стоимость считает сам Claude Code по ценам API (`total_cost_usd`, `costBasis: list`). При входе по подписке это эквивалент, а не списание. Codex сообщает только токены.
- Прогон, остановленный кнопкой, свой расход не сообщает и записывается без токенов.
- Прогоны версий, собранных до учёта, один раз читаются из их `agent.log` при запуске сервера.
- Удалённый ролик уходит из статистики вместе со своими прогонами.

## Графика

`gfx/src` — шаблон Remotion: видео склейки, субтитры по словам, встроенные элементы (`title`, `fullscreen`, `list`, `stat`, `lowerThird`, `callout`, `zoom`, `chat`, `sticker`) и свои компоненты агента из `custom/`. Агент описывает графику в `graphics.json` временем исходника, поэтому она переживает перемонтаж. Встроенный `action` рисует схему процесса «субъект → действие → объект → результат» с простыми иконками, `chat` — окно чата с набираемым вопросом и ответом, `sticker` — готовую иллюстрацию пакета.

Агент не рисует персонажей и предметы кодом: это давало вид любительской флеш-анимации. Вместо этого у него есть:

- **иллюстрации пакета** (`illustrations.json`): в «Базовом» 195 объёмных картинок Microsoft Fluent Emoji 3D (MIT) — люди, эмоции, жесты, техника, документы, деньги, время, предметы; список — `illustrations.md` в папке версии, листы с id — `cutroom gfx illustrations`;
- **набор интерфейса** в модуле `cutroom` (`gfx/src/kit.tsx`): окно приложения, телефон, чат с `chatAt`, уведомление, документ, кнопка, переключатель, строка настроек, прогресс, курсор, иконки, `Illustration`; справочник — `instructions/guide/kit.md`;
- **библиотека движений** (`gfx/src/moves.ts`): кривые `ease`, пружины `springs`, входы, набор текста, счётчик, нажатие, путь курсора, тряска, перенос между сценами (`morph`, `zoomThrough`, `iris`), камера по ключам; лист с шестью кадрами каждого — `cutroom gfx moves`, справочник — `instructions/guide/motion.md`;
- **стили** (`looks` в `pack.json`): именованные цвета и шрифты, агент выбирает `look` в `graphics.json`. У «Базового» четыре: «Ночь», «Бумага», «Чистый», «Неон» (шрифты Montserrat, Manrope, PT Serif, Unbounded, OFL).

`cutroom gfx check` отклоняет компонент, который рисует персонажа фигурами SVG, и две полноэкранные сцены встык без переноса (`carry` в карте или общий элемент), а сцены одной длины помечает как метроном. `cutroom gfx review` кроме листа элементов рендерит лист сцен (начало, середина, конец каждой) и меряет, что остаётся в кадре на стыке полноэкранных сцен: меньше 40% — стык-слайд, ошибка, и worker возвращает ответ на второй заход (неподвижное окно с подменой содержимого набирает 20–50%, настоящий перенос — больше). После проверки агент выступает строгим критиком и пишет `critique.md`: без него worker возвращает ответ на второй заход.

До графики агент пишет раскадровку `scenes.json` (формат `cutroom-scenes-v2`): сквозной образ ролика, а для каждой сцены — что на экране, что это даёт зрителю сверх голоса, приём (сам предмет, пример, образ автора, было/стало, число, схема, текст) и какой текст выходит на экран. Агент может придумывать иллюстративные примеры и перечисляет их в `reply.md`. `cutroom gfx check` и worker после агента проверяют, что каждая сцена с графикой есть в карте, у неё заполнены эти поля, один встроенный шаблон (`action`, `fullscreen`, `list`, `stat`) не стоит в большинстве сцен и трижды подряд, на экране не больше 10 слов, фраза из трёх и больше смысловых слов не повторяет то, что автор говорит в этот момент (включая предложение, разбитое на строки), а текст в своих компонентах назван в карте. Набор текста со скрытыми субтитрами — исключение: продиктованный текст для повторения агент печатает слово в слово. Карты старого формата `cutroom-scenes-v1` проверяются по прежним правилам. Найденное уходит агенту на второй заход вместе с проверкой раскладки; что осталось, видно в сообщении версии. Формат и правила — в [instructions/AGENTS.md](instructions/AGENTS.md#графика).

### Движки клипов

Для полноэкранной сцены с настоящей анимацией агент может собрать отдельный клип на другом движке, отрендерить его в видео (`clips/<имя>.mp4`) и поставить в ролик вставкой `video`. Склейка, субтитры, графика вокруг лица и звук остаются в Remotion. Клип получает шрифты пакета и цвета выбранного стиля (`look.css`), рендерится в финальном размере и проходит раскадровку и проверки как любая сцена. Команды — `cutroom clip new|check|still|render|run|look`, правила для агента — [instructions/guide/clips.md](instructions/guide/clips.md).

- **HyperFrames** (HeyGen, Apache 2.0) встроен в образ: CLI закреплённой версии и навыки `hyperframes`, `hyperframes-cli`, `hyperframes-registry` с того же тега. Умеет прозрачный фон (`--alpha` → `.webm`), тогда клип — слой поверх автора. Телеметрия, проверка обновлений и автоустановка выключены.
- **onetake** (PolyForm Noncommercial 1.0.0) Cutroom не распространяет. Автор ставит его в «Настройки → Клипы и картинки» из официального репозитория закреплённой ревизии после предупреждения: бесплатная версия — только для некоммерческого использования, для клиентов и бизнеса нужен [onetake Pro](https://onetakemotion.com); соблюдение лицензии — на авторе. Ставится в `/data/engines/onetake` со своим Python и Chromium (около 760 МБ), Pro — загрузкой купленного архива поверх. Каждый движок можно выключить.

Включённые движки агент видит в `engines.md` версии, их навыки — в `.claude/skills/` и `.agents/skills/`. Перемонтаж наследует `clips/` прошлой версии.

### Сгенерированные картинки

Если нужного предмета или сцены нет ни у автора, ни в иллюстрациях пакета, агент может сгенерировать картинку: `cutroom image new <имя> --prompt "…"`. Генерирует Codex CLI автора по подписке ChatGPT (его встроенный инструмент картинок), монтировать при этом может и Claude Code. Cutroom не обращается к API картинок сам и не видит ключи: он запускает `codex exec` в пустой папке, добавляет к описанию стиль пакета (`imageStyle` в `pack.json`) и запреты (без текста, логотипов и реальных людей) и сохраняет PNG в `images/<имя>.png` версии с записью в `images/images.json`. Картинка ставится элементом `sticker` (`props.file`) без фона или `image` сценой. Лимит — от 1 до 10 картинок на ролик (по умолчанию 3), каждую можно переделать дважды; перемонтаж наследует `images/`, и лимит считается на ролик. Включается и настраивается в «Настройки → Клипы и картинки», доступно, пока Codex подключён. Правила для агента — [instructions/guide/images.md](instructions/guide/images.md).

Превью с графикой рендерится в 720p, финал — 1080p по короткой стороне. Remotion бесплатен для физических лиц и компаний до трёх сотрудников; для большей компании нужна лицензия Remotion.

## Интерфейс

`web/` — React, Vite, Tailwind и shadcn/ui; чат на компонентах prompt-kit. В образе собирается в статические файлы, их отдаёт `app`.

Разработка интерфейса с горячей перезагрузкой при запущенном Cutroom:

```bash
cd web && npm install && npm run dev
```

Vite проксирует `/api`, `/media` и терминал на `localhost:8080`.

## Локальный запуск

Нужен Docker Desktop и checkout OpenRoughCut с пакетом `packages/core`.

```bash
./install.sh --source . --orc ../VideoEditor
```

Первая сборка занимает несколько минут: whisper.cpp, FFmpeg, агенты. В конце скрипт напечатает адрес и пароль. Открыть: http://localhost:8080.

Дальше:

1. Онбординг: выбрать агента и войти в него в терминале (`claude`, затем `/login`, или `codex login --device-auth`), описать вкус и бренд. Можно пропустить и работать «Без агента».
2. «Новый ролик» → загрузить запись → «Отправить в монтаж».
3. Посмотреть версию, написать правку в чат → «Перемонтировать».
4. «Принять» — worker рендерит финал в полном разрешении.

Первый монтаж скачивает модель Whisper (около 470 МБ для `small`).

## Сервер

Образ публикуется в `ghcr.io/tomfordrumm/cutroom` для amd64 и arm64. Если Docker уже стоит, установщик берётся прямо из образа:

```bash
docker run --rm --entrypoint cat ghcr.io/tomfordrumm/cutroom:latest /opt/cutroom/release/install.sh | sudo bash -s -- --domain cut.example.com
```

Без Docker на Linux: `sudo bash install.sh --domain cut.example.com`, скрипт поставит Docker сам. Установщик создаёт `/opt/cutroom` с `compose.yml`, `update.sh` и `.env` (случайный пароль) и поднимает app, worker и Caddy. DNS-запись домена нужно направить на сервер заранее. `--image ghcr.io/tomfordrumm/cutroom:0.2.0` закрепляет версию.

## Обновления

- **Выпуск.** Поднять `version` в `package.json`, закоммитить и поставить тег `vX.Y.Z`. GitHub Actions (`.github/workflows/release.yml`) проверит, что тег совпадает с `package.json`, прогонит тесты в образе и опубликует `:X.Y.Z` и `:latest`. OpenRoughCut встраивается на коммите из `orc.ref`. Сборка для двух архитектур занимает около часа.
- **Что видит владелец.** «Настройки → Обновления»: текущая версия, вышла ли новая, команда обновления. Cutroom раз в 6 часов спрашивает у реестра список тегов образа — тот же запрос, что делает `docker pull`. `CUTROOM_UPDATE_CHECK=off` в `.env` выключает проверку.
- **Обновление.** `cd /opt/cutroom && sudo ./update.sh`. Скрипт:
  - скачивает новый образ и берёт из него свежие `compose.yml` и `update.sh`;
  - ставит очередь на паузу: начатый монтаж доработает, новые ролики подождут;
  - перезапускает Cutroom; новый worker снимает паузу.

  `./update.sh 0.3.0` ставит конкретную версию, в том числе более старую. `--now` не ждёт идущий монтаж, он прервётся. Ctrl+C во время ожидания отменяет обновление и снимает паузу.
- **Что сохраняется.** Ролики, версии, настройки, вход в Claude Code и Codex, установленные пакеты вкуса — всё в томе `cutroom-data`. Инструкции агента и базовый пакет приходят с образом. Свой пакет (например, «Свят404») обновляется отдельно, установкой нового zip.
- **Установка из исходников** (`--source`): получить новый код (`git pull`), затем `./update.sh` в checkout. Он соберёт образ и так же дождётся конца монтажа.
- **Пока образ закрыт** (пакет на ghcr приватный), пользователю нужен `docker login ghcr.io`, а проверка версии в настройках пишет «образ закрыт или ещё не опубликован». Открытый пакет снимает оба ограничения; исходный код при этом остаётся закрытым.

## Команды

```bash
docker compose logs -f worker      # что делает очередь
./update.sh                        # обновить или пересобрать, дождавшись конца монтажа
docker compose down                # остановить (данные остаются в томе)
docker compose down -v             # остановить и удалить ВСЕ данные
```

## Структура ролика

```
/data/library/music|sfx|other/    библиотека автора, общая для всех роликов
/data/videos/<id>/
  sources/<запись>
  assets/                         материалы ролика
  analysis/<отпечаток>/review.json, media.json, asr.json   Whisper и дубли, один раз на запись и модель
  versions/v001/
    request.json                бриф, правки, предыдущая версия
    AGENTS.md, CLAUDE.md        инструкция монтажёра
    taste.md, transcript.md, review.json, layout.md, illustrations.md, faces.json, dictionary.md, media.md
    guide/                      справочники агента: elements.md (graphics.json), kit.md (API своего
                                компонента), motion.md, storyboard.md (образец раскадровки), clips.md,
                                images.md, revisions.md; тест
                                test/guide.test.js сверяет их с экспортами модуля cutroom
    engines.md, .claude/skills/, .agents/skills/   включённые движки клипов и их навыки
    pack/                       копия пакета вкуса этой версии
    decisions.json, overrides.json, scenes.json, graphics.json, custom/, clips/, dictionary.json, remember.json, critique.md, reply.md    ответ агента
    media/library/…, media/sounds/…, media/assets/…   файлы, которые использует graphics.json
    gfx-review.json             проверка раскладки графики
    sound.json                  громкость файлов музыки и эффектов (LUFS)
    edit.json                   рецепт версии: источник, решения, оставленные куски
    build.json, agent.log
    out/preview.mp4, report.json, final.mp4
```

`edit.json` — источник правды версии; видео выводятся из него. Перемонтаж создаёт новую папку и не трогает старые.

## Подписки

- Claude Code: пользователь входит своей подпиской в неизменённый CLI через собственный поток Anthropic. Cutroom не читает, не хранит и не передаёт токены, проверяет только наличие файла входа. Перед распространением продукта нужно отдельно проверить условия Anthropic (Commercial Terms, название без «Claude Code»).
- Codex CLI: вход через `codex login --device-auth`. Условия OpenAI для такого использования не проверены.

## Ограничения 0.1

- Один исходник на ролик; новая загрузка заменяет старый.
- Графика рендерится на CPU: 35 секунд превью 720p — около двух минут.
- Агент видит расшифровку, звуки без слов и может вытащить кадры через FFmpeg; инструментов прослушивания нет.
- Правки к секунде: кнопка «Комментарий» или клавиша C на таймлайне версии; агент получает время в версии, время в исходнике и слова рядом.
- Загрузка одним запросом, без докачки (tus — позже).
- Один пароль владельца, без ограничения попыток входа.
